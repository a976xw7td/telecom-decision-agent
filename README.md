# 电信经营决策 Agent v1.0.0 · 可运行 Agent 与证据验证

挑战③交付物：一个**离线、确定性、可独立打开**的经营决策应用，把 Agent / Skill / RAG / 工作流串成一条可复现的证据链。

- 应用标识：`agent.telecom-ops-decider` **v1.0.0** / build **20261125.2**
- 形态：单文件 HTML 界面（`index.html`）+ 本地规则引擎（`engine.js`），双击即可运行，**不联网、不需要安装、不需要账号**
- 数据窗口：2026-W36 ~ 2026-W40（5 周，教学样例）
- 验证结论：五类测试真实执行 **20 / 20 PASS**（`evidence/run-log.md`）

## 1. 启动步骤

### 方式 A：直接打开界面（推荐，验收用）

1. 双击 `index.html`（或用浏览器打开该文件的本地路径）。
2. 页面左上角显示 `agent.telecom-ops-decider v1.0.0 · build 20261125.2`，即版本标识生效。
3. 在输入框输入问题 → 点「运行」→ 看到五段式流水线依次点亮，下方输出「结论 / 依据 / 待补证据」。

> 若浏览器拦截脚本读取本地 `engine.js`（部分浏览器的 `file://` 限制），按方式 B 起一个本地静态服务，二者输出完全一致。

### 方式 B：本地静态服务

```bash
cd telecom-decision-agent
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000/index.html
```

### 方式 C：只跑引擎与测试（复核用，无界面）


`run-tests.js` 会打印 20 条用例的「预期 / 实际 / 结果」对照表，并在 `evidence/` 下重新生成运行记录；同一输入重复运行结果完全一致。

## 2. 模型与授权

| 项 | 说明 |
| --- | --- |
| 模型 | **未接入任何外部大模型 API**。全部判断由本地规则引擎 `engine.js` 计算，kind = `rule-based-deterministic` |
| 授权 | 无第三方模型服务、无 API Key、无供应商条款约束；无需申请配额 |
| 凭证 | 应用内**不含任何凭证、Token、Cookie、密钥**；代码与数据均无敏感字段 |
| 可解释性 | 每条结论都能回溯到「口径条目编号（KB-xx）+ 具体数值 + 计算公式」，不存在黑箱打分 |

**为什么不用大模型**：本挑战要求「同一输入 → 同一输出」的可复现证据。规则引擎能做到完全确定（20/20 复跑一致），而外部模型会引入供应商波动与不可控成本；经营口径类判断（ARPU、万投比、离网率）本质是公式复算，规则化反而更可审计。

## 5. 已知限制（如实声明）

1. **数据只有 5 周**。趋势判断只能覆盖 W36–W40，不能外推季节性；任何「全年」结论都不成立。
2. **分群样本偏小**。`中区融合用户` 仅 180 户 / 22 单，低于 500 户 / 30 单下限，因此所有分区对比类问题会被主动拦截，只能输出全市级结论。
3. **无竞品价格数据**。涉及「竞品降价是否跟进」的问题，引擎只给待补证据清单与取证路径，不给业务结论。
4. **无毛利/成本口径**。缺毛利率与单户成本，因此不输出 ROI、回本周期等收益结论（What-if 只给「月挽留户数」与其敏感区间）。
5. **规则引擎是「窄而深」**。它只覆盖经营周报这一类问题；问组织、人事、网络工程等议题会落到「待补证据」，不会编造。
6. **未接入企业实时系统**。数据靠 `engine.js` 内置常量，换数据需替换 `WEEKS` / `MIDWEEK` 两个常量对象（见 `skill/SKILL.md` 第 6 节换数流程）。
7. **界面层前置校验**。非数字坐席输入由前端拦截；直接调引擎函数传非法值会得到 `NaN`，属预期行为（用例 X-1 已记录）。
